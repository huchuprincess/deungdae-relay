# 기상특보와 지진 조회용 공개 중계 준비

서비스키를 수신 앱에 넣지 않고 공식 공공데이터만 정적 JSON으로 배포할 독립 중계가 필요합니다. 실패나 미조회 상태를 특보 없음으로 오인하지 않아야 합니다.

로컬 후보에는 Python 표준 라이브러리 수집과 검증 코드, 직접 만든 예제, 미조회 상태 JSON, 키 없는 테스트, R2 기본 배포와 비활성 Pages 대체 구성이 있습니다. 두 피드의 실패, 오래된 응답과 마지막 유효 자료 유지가 각각 검증되어야 합니다.

특보 목록만으로 현재 지역의 활성 상태를 추측하지 않습니다. 공식 현황 API 구조를 확인하기 전에는 적용, 해제, 만료 시각을 미확인으로 두고 특보 없음 표시를 하지 않습니다. 지진은 발생 시각이 있는 과거 발표 기록으로 취급합니다.

공개 전 전체 파일과 새 커밋 기록, 설정, 예제, 로그, 의존성과 권한을 검사해야 합니다. 앱 코드, 개인정보, 비밀값과 내부 저장소 정보는 공개 범위에 포함하지 않습니다. 수집 자료의 출처와 이용 조건을 유지하고 불명확한 자료는 넣지 않습니다.

실서비스 확인에는 두 API 활용신청과 실제 응답 시험, 특보 현황 정의, R2 계정과 도메인 준비가 남아 있습니다. Pages 이용 적합성과 코드 라이선스도 소유자가 확인해야 합니다.

Pages 배포 의존성에서 알려진 취약점이 발견되어 배포 작업을 코드에서 잠갔습니다. CI와 R2 경로는 해당 외부 Action을 제거했습니다. Pages 의존성 문제를 해소하고 재검사하기 전에는 잠금을 풀지 않습니다.

이 파일은 원격 이슈 생성 전의 본문 초안입니다. 공개 저장소 생성 승인 후 이슈를 먼저 만들고 그 번호를 변경 설명과 draft PR에 반영합니다.
