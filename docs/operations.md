# 운영 준비

현재는 계정과 키를 만들거나 설정하지 않은 상태입니다. 아래는 승인 후 사용할 구성 설명이며, 이 문서만으로 공개 저장소 생성이나 배포를 승인하지 않습니다.

## 기본 경로: R2

R2 Standard 버킷의 `v1/latest.json`을 자체 HTTPS 도메인으로 제공합니다. 계정, 결제 설정, 버킷, 도메인, 예산과 접속정보 처리 조건을 소유자가 먼저 확인해야 합니다. 개발용 `r2.dev`를 운영 주소로 쓰지 않습니다. 지도 파일은 이 프로젝트에 넣지 않습니다.

수집 전에 해당 R2 객체를 서명된 GET으로 읽어 마지막 유효 자료를 복원합니다. GET 실패, 손상된 JSON이나 필요한 ETag 누락은 작업 전체를 중단합니다. 처음 객체가 없는 경우에만 `ALLOW_EMPTY_BASELINE=true`로 빈 초기 상태를 허용하며 최초 성공 뒤에는 이 변수를 해제합니다.

저장은 PUT 한 번으로 완료합니다. 이전 객체의 ETag를 `If-Match`에 넣고, 최초 생성은 `If-None-Match: *`를 씁니다. 충돌이나 PUT 실패 뒤에는 조건 없는 재시도나 삭제를 하지 않습니다. 기존 객체가 그대로 남습니다. Actions의 동시 실행도 직렬화합니다.

R2 객체에는 `Content-Type: application/json; charset=utf-8`과 `Cache-Control: public, max-age=0, s-maxage=300, must-revalidate`를 설정합니다. 자체 도메인의 JSON 캐시 적격성, 원본 헤더 존중, 실제 ETag/304 동작은 설정 후 시험해야 합니다. 지도용 장기 캐시 규칙을 이 경로에 적용하지 않습니다. 파일을 새로 내려받아도 피드의 마지막 성공 시각으로 지연을 판단합니다.

## 대체 경로: Pages

예정 주소는 `https://huchuprincess.github.io/deungdae-relay/v1/latest.json`입니다. 저장소와 Pages가 없으므로 현재 사용 가능한 주소가 아닙니다. Pages용 산출물은 JSON 두 개, 안내 HTML과 `.nojekyll`뿐이며 소스, 비밀값이나 작업 상태 파일을 올리지 않습니다. Pages 배포 의존성에서 알려진 취약점이 발견되어 build와 deploy 작업을 모두 `false` 조건으로 잠갔습니다. 승인 변수만으로 이 잠금을 풀 수 없습니다. [의존성 검사](dependencies.md)의 문제를 해소하고 코드 검토를 받은 뒤에만 잠금을 풀 수 있습니다.

R2를 사용할 수 없을 때 자동으로 과거 Pages 자료를 R2로 되돌려 쓰지 않습니다. 이용 목적과 약관, 사용량, 캐시와 실서비스 응답을 확인한 뒤 `RELAY_DELIVERY=pages`를 명시적으로 선택하는 대체 구성입니다. R2와 Pages를 함께 갱신하는 구성은 이번 후보에 없습니다. 두 경로 간 마지막 유효 자료를 인계하고 수신 앱의 배포 주소를 바꾸는 절차도 전환 전에 시험해야 합니다.

Pages는 캐시 헤더를 이 프로젝트에서 제어할 수 없습니다. 수신자는 저장된 성공 시각과 캐시 검증을 계속 확인해야 합니다. 이전 Pages JSON을 읽지 못하면 새 사이트를 배포하지 않습니다. 배포가 실패하면 이전 성공 배포가 남습니다. `public/v1/latest.json`의 미조회 상태를 이전 실서비스 파일 대신 사용하지 않습니다.

## 예약 작업과 설정

CI는 키 없는 테스트와 공개 후보 검사만 실행합니다. 수집 작업은 기본적으로 비활성입니다. `main`의 승인된 코드에서 다음 저장소 변수를 설정해야 실행됩니다.

| 변수 | 준비할 값 |
|---|---|
| `RELAY_PUBLICATION_APPROVED` | 공개 범위를 다시 승인한 뒤에만 `true` |
| `LIVE_API_VERIFIED` | 공식 활용가이드와 실제 응답, 오류와 빈 응답을 검증한 뒤에만 `true` |
| `RELAY_DELIVERY` | 기본 `r2`, 검토한 대체 경로는 `pages` |
| `PAGES_PUBLICATION_APPROVED` | Pages 검토와 별도 배포 승인 후에만 `true` |
| `ALLOW_EMPTY_BASELINE` | 최초 자료 생성 때만 `true`, 이후 해제 |

서비스키는 `DATA_GO_KR_SERVICE_KEY`, R2 설정은 `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`라는 작업 비밀값으로 받을 수 있게 준비했습니다. 이 후보에는 값이나 계정 예시를 넣지 않았습니다. 공공데이터포털의 두 서비스 활용신청 조건, 한도와 운영 계정 절차를 확인해야 합니다. 현재 키, R2 토큰, OAuth 권한은 새로 만들지 않았습니다.

수집 간격은 10분입니다. Actions 예약은 지연이나 중단될 수 있으므로 10분 갱신을 보장하지 않습니다. 중계가 실행되지 않아도 수신 측에서 30분 지연을 계산합니다. 작업 결과 파일을 매번 Git에 커밋하지 않으며 원본 응답, 요청 헤더나 인증 정보를 아티팩트로 남기지 않습니다.

실제 키가 생긴 뒤에도 먼저 비공개 작업에서 원본 형식, ServiceKey 파라미터 처리, Date/Age, 빈 응답과 오류 코드, 페이지 수와 게시 시각을 확인해야 합니다. 계정 없이 수행한 테스트를 실서비스 확인으로 취급하지 않습니다. 특보 현황과 적용, 해제 필드의 공식 정의가 확보되기 전에는 지역별 활성 특보나 `특보 없음` 표시를 추가하지 않습니다.

Actions는 `contents: read`만 기본으로 사용합니다. CI와 R2 수집은 외부 checkout Action을 쓰지 않고 고정된 공개 저장소에서 네이티브 Git으로 요청 ref를 가져온 뒤 실행 SHA를 일치시킵니다. 인증이나 자격 증명 helper를 쓰지 않으며 훅과 로컬 파일 프로토콜을 차단합니다. Pages 배포 작업에만 `pages: write`, `id-token: write`를 준비했지만 현재는 코드에서 잠겨 있습니다. 이 권한을 요청하거나 실행하지 않았습니다. 환경 보호와 비밀값 접근 범위는 공개 승인 후 기존 권한 안에서 설정하며 별도 OAuth 승인을 만들지 않습니다.
