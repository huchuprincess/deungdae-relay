# 자료 계약

배포 파일은 `v1/latest.json` 하나입니다. `schemaVersion`은 1이며 코드의 `relay.model.validate`가 허용한 필드만 저장합니다. 두 피드가 한 객체에 있어 읽는 동안 서로 다른 파일 세대가 섞이지 않습니다. 모든 공개 시각은 초 단위 UTC의 `Z` 형식입니다. 기상청의 숫자형 시각은 한국 시각으로 해석한 뒤 변환합니다.

| 값 | 뜻 |
|---|---|
| `mode` | `unconfigured`는 실제 조회 전, `example`은 직접 만든 예제, `live`는 실서비스 조회 경로 |
| `notice` | 자료 종류를 명시하는 고정 문구 |
| `generatedAt` | 이 파일의 작성 시각, 원본 발표나 피드 성공 시각이 아님 |
| `feeds.weather`, `feeds.earthquake` | 각각 독립적인 출처, 조회 결과와 마지막 유효 자료 |
| `lastAttemptAt` | 마지막 조회 처리가 끝난 시각 |
| `lastAttemptStatus` | `not-requested`, `unconfigured`, `success`, `failure` |
| `lastSuccessAt` | 유효한 응답 전체를 검증한 마지막 시각, 실패 때 유지 |
| `failureCode` | 미리 정한 오류 코드, 원본 에러 문구나 요청 URL을 넣지 않음 |
| `data` | 마지막 유효 자료, 한 번도 성공하지 않았으면 `null` |
| `sourceResponseAt` | 원본 HTTP 응답의 Date, 원본 자료 관측 시각을 보장하지 않음 |
| `queryFrom`, `queryTo` | 한국 날짜 기준 직전 7일과 당일을 포함한 발표 조회 범위 |
| `coverage` | 특보는 `bulletin-history`, 지진은 `event-history` |
| `regionStateVerified` | 현재 후보에서는 항상 `false` |

특보 기록에는 제목, 발표 시각과 지점 코드가 있습니다. `effectiveAt`, `releasedAt`, `expiresAt`은 미확인을 뜻하는 `null`, `state`는 `unconfirmed`입니다. 제목에 발표나 해제라는 말이 있어도 상태나 시각을 추측하지 않습니다. 지진은 `publishedAt`과 `occurredAt`을 따로 보존하며 `state`는 `reported`입니다. 진앙 좌표는 공개 사건의 좌표이고 사용자 위치를 받는 기능은 없습니다.

HTTP 응답의 Date나 Age가 30분을 넘겼거나 Date가 없으면 성공으로 받아들이지 않습니다. 이전에 저장한 HTTP 응답 시각보다 오래된 응답도 거부합니다. 이전 기록의 발표 날짜가 새 조회 범위와 겹칠 때 새 기록이 비어 있거나 가장 최신 `publishedAt`이 이전보다 이르면 마지막 자료와 성공 시각을 유지합니다.

이 검사는 같은 조회 범위의 모든 기록을 보존하는 기능이 아닙니다. 유효한 새 응답의 가장 최신 `publishedAt`이 이전과 같거나 더 늦으면, 그보다 오래된 일부 기록이 빠져 있어도 응답 전체를 새 목록으로 교체하고 성공 시각을 갱신합니다. 누락 기록을 이전 목록에서 합쳐 넣거나 개별 기록의 수정과 삭제를 판별하지 않습니다. 실제 API가 기록을 수정하거나 삭제하는 방식과 이때의 발표 시각 변화는 아직 검증하지 않았습니다. 해당 검증 전에 기록 보존이나 수정·삭제 반영의 완전성을 주장하지 않습니다.

발표가 오래된 것과 조회가 오래된 것은 별개입니다. 새 지진이 없으면 과거 발표 기록을 성공 응답으로 받을 수 있지만 현재 사건으로 표시하지 않습니다.

수신자는 10분보다 자주 요청하지 않고 ETag 또는 Last-Modified로 HTTP 캐시를 검증합니다. 304도 JSON 속 마지막 성공 시각을 갱신하지 않습니다. 파일 생성 시각이나 다운로드 시각으로 피드를 새 자료처럼 표시하지 않습니다. 30분을 넘겨 성공 시각이 갱신되지 않으면 `갱신 지연`, 새로운 조회에 실패하면 `조회 실패`를 표시합니다. 둘이 겹치면 실패와 지연을 함께 구별하며 마지막 성공 자료는 그 시각과 함께 참고로만 표시합니다. 중계가 멈춘 뒤에도 수신자가 현재 시각으로 지연 여부를 다시 계산해야 합니다.

`relay.model.presentation`은 이 규칙의 참고 구현입니다. 예제와 미조회, 통신 단절, 실패, 오래된 성공 응답, 해제나 만료된 특보를 현재 활성 특보나 안전으로 바꾸지 않습니다. 유효한 시각의 지역별 활성 특보 현황을 확인한 경우에만 `특보 없음`이 가능하지만 현재 후보의 목록 경로에는 그 확인 기능이 없습니다. 따라서 `noWarningsConfirmed`는 항상 `false`이고 `earthquakeIsCurrent`도 항상 `false`입니다. 이 값은 JSON의 사건 상태를 자동 경보로 쓰기 위한 값이 아닙니다.

지역 선택과 사용자 위치에 따른 계산은 수신 기기에서 해야 합니다. 이 프로젝트는 기기 상태, 건강, 가족 정보, 저장한 장소나 사용자 식별자를 받지 않습니다. 내장 안내와 저장 자료의 오프라인 동작은 수신 앱의 책임이며, 이 중계 자료를 그 진입 조건으로 두지 않습니다.
