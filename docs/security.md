# 보안과 공개 절차

공개 후보는 `PUBLIC_FILES.txt`에 적힌 텍스트 파일뿐입니다. 후보에는 앱 소스, 개인정보, 내부 저장소 경로, 원본 정부 응답이나 실제 운영 계정 값이 없습니다. 예제는 `synthetic: true`로 표시한 직접 만든 자료입니다. 의존성 소스나 검사 도구의 실행 파일도 후보에 포함하지 않습니다.

검사는 허용 파일 목록, 파일 해시, 링크와 실행 권한, 알려진 비밀정보 패턴과 긴 토큰 형태, 개인정보 패턴, 설정과 Actions 권한, 테스트 자료와 정적 JSON을 확인합니다. 알려진 운영 비밀값이 실제 출력에 섞이면 그 값을 가리지 않고 해당 출력을 거부합니다. 프로세스는 정해진 상태와 오류 코드만 기록하며 원본 오류, URL, 헤더, 환경 변수나 응답 본문을 로그에 출력하지 않습니다. GitHub의 자동 가림 기능은 안전 보장으로 취급하지 않습니다.

새 로컬 후보 이력은 공개 파일 목록만 포함하는 독립적인 초기 커밋으로 준비합니다. 도달 가능한 커밋뿐 아니라 삭제된 변경을 포함한 모든 로컬 Git 객체도 읽습니다. 커밋과 태그의 작성자 정보, reflog, 원격 설정, 훅, 실행 비트, 링크와 서브모듈을 확인합니다. 비공개 기록을 복사하거나 가져오지 않습니다. 실제 후보 이력도 검사하며, 삭제된 객체의 탐지 기능은 임시 시험 저장소에서 지운 비밀값과 개인정보가 남은 커밋으로 별도 검증합니다.

패턴 검사는 알 수 없는 비밀값을 모두 찾아낸다는 보장이 아닙니다. 공개 직전에 전체 파일과 변경 내용을 다시 읽고, 실제 운영 로그가 생기면 그 로그도 별도로 검토해야 합니다. 작성자 표시는 저장소용 식별자와 `users.noreply.github.com` 형식의 주소를 사용하며 실제 이름과 개인 이메일을 이전 설정에서 가져오지 않습니다. 이 주소 형식만으로 특정 GitHub 계정과의 연결이 확인됐다고 주장하지 않습니다.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/check_candidate.py --report /tmp/relay-audit.json
PYTHONDONTWRITEBYTECODE=1 python3 scripts/export_candidate.py --output /tmp/deungdae-relay-export
```

내보내기는 검사를 통과한 허용 파일만 새 폴더에 복사하고 파일 권한을 0644로 맞춥니다. `.git`이나 생성된 파일은 복사하지 않습니다. 출력 폴더는 아직 존재하지 않는 경로를 지정합니다. 별도 검토 기록과 로그는 공개 후보 바깥에 둡니다.

로컬 출력 경로는 작업 소유자가 직접 관리하는 디렉토리를 사용합니다. `atomic_write`는 출력 파일 자체의 심볼릭 링크를 거부하지만 부모와 상위 경로의 링크, 검사 중 경로 변경은 차단하지 않습니다. 내보내기 경로도 `resolve()`로 해석하므로 부모의 링크를 모두 거부하는 기능이 아닙니다. 원자적 파일 교체와 파일 목록 검사를 임의 경로에 대한 쓰기 격리로 설명하지 않습니다.

공개 단계의 순서는 소유자 승인, 저장소 생성, 이슈 생성, 그 번호를 반영한 변경 기록과 draft PR, 추가 검토입니다. 변경 설명은 `Refs #번호`를 사용합니다. 현재는 저장소 생성이 승인되지 않았으므로 이슈와 PR을 원격에 만들지 않았습니다. 배포 승인도 별도로 확인해야 합니다.

코드 라이선스, 실제 특보 현황 구조, R2 계정과 도메인, Pages의 상업 앱 보조 배포 적합성은 공개나 운영 전에 확인할 항목입니다. 이 후보에서 새 결정을 추측해 확정하지 않았습니다.

의존성 검사에서 발견한 Pages 배포 문제는 [별도 결과](dependencies.md)에 기록했습니다. CI와 R2 수집 경로에서는 해당 의존성을 제거했고 Pages 구성은 실행되지 않도록 잠갔습니다. 파일 검사 통과를 모든 배포 경로의 운영 승인으로 해석하지 않습니다.
